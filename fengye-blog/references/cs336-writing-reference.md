## 实际反馈如何变成写法

### 从已经看到的东西引入概念

用户反馈：直接说“残差连接就是……”太突然，读者还不知道为什么这里出现这个名词。

合适的衔接示例：

迁移到其他主题：先指出代码或图里的具体操作，再给名称和用途。不要脱离上下文开一段词典式定义。

### 一条公式不必一次讲完

RMSNorm 一节的有效顺序是：每个 token 的向量单独计算 → 平方、平均、开根得到 RMS → 每个分量除以 RMS → 乘可学习的缩放参数 → 短例子 → 对应实现。

符号必须落到对象：`d_model` 是一个 token 向量的分量数，`seq_len` 是序列里的 token 数；不能混为一谈。`g_i` 是第 i 个分量的缩放参数，说明是否学习、如何共享。需要用 D 简写时先明确 D 与 `d_model` 的对应关系，不把新字母当成默认知识。

迁移到其他主题：把复合计算拆成读者能逐步跟上的操作。符号解释紧挨着公式，不另堆一大段定义。

### 解释变化和优势时，把对象说准

RoPE 一节反复修改的重点：

- 位置先决定 q、k 的旋转角度，再通过角度差影响点积和注意力权重。
- 旋转保持长度与形状；v 不做这一步旋转；权重和输出会受位置影响。不能笼统地说“其他计算不受影响”或“点积不变”。
- “相对位置不变时点积相同”需要固定旋转前的 q、k；不是声称任意上下文中相距相同的 token 分数都一样。
- 对比对象是“把位置向量加到 token Embedding 上”。讲清相对位置如何直接进入匹配关系，不能只复述两种实现。

用户更容易理解单对二维分量的余弦式：

$$
q'\cdot k'=\lVert q\rVert\lVert k\rVert\cos[\delta+(j-i)\omega]
$$

在相邻文字里说明：δ 是从 q 到 k 的有向角度差，i、j 是位置，ω 是该分量对的旋转频率，双竖线表示长度。图也画同一角度关系；完整向量的点积由各分量对的贡献相加得到。不要拿另一套数字图再让读者自己对应矩阵式。

### 计算题保留短过程

用户指定的格式是：

1. **参数量和内存：** 我们要计算哪些参数、存储需要多少内存？

   说明统计口径，按模块相加，代入配置，再给总量和单位。

2. **一次前向传播的计算量：** 哪些矩阵相乘，一共多少 FLOPs？

   用一个投影解释 `2mnp` 怎么套，其他计算列小表，相加得到结果。

后续占比、不同模型规模、不同序列长度也各自接短计算和结论。可复用的是“问题后紧接计算”，不是要求每篇文章都套五个问题或展开到同样篇幅。
