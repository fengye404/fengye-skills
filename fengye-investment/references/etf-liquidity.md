# ETF历史成交、订单规模与成本参考

`scripts/etf_liquidity.py`读取 `market_research.py fetch` 保存的快照，用**实际人民币成交额**补充瞬时盘口。借鉴stock-liquidity的ADV/中位数/订单参与率与价差拆解，排除美股分级、主观综合评分和未校准的冲击模型。

## 执行

```bash
INVEST_PY=/Users/fengye/workspace/investment/.venv/bin/python
"$INVEST_PY" scripts/etf_liquidity.py \
  --bundle /path/to/market.json --amount-unit CNY --windows 20,60 \
  --order-amount 10000 --commission-rate 0.0001 --minimum-commission 0 \
  --side buy --out /path/to/new-liquidity-results
```

这是分别考察每只ETF的一万元假设订单，不是把每只都新增一万元。万一免五等费率由调用者明确填写，脚本不假定账户费率已被券商核实。不指定订单金额时仅做历史流动性；佣金费率未指定时保持未知。输出目录拒绝覆盖，包含原始行情副本及SHA、`liquidity.json`和`report.md`。

先核验源端 `amount` 的单位，再声明 `--amount-unit CNY`。本地已用AKShare 1.19.1的 `stock_zh_a_hist_tx` 接口确认amount规范化为元；不同接口/版本必须重核，不把万元或美元直接混入。无实际成交额时拒算，不静默改用收盘价×成交量。

## 指标与缺失处理

- 每个20/60窗口报告实际样本数、起止日期、已知成交额的均值/中位/P10/最小值，以及相对这些分母的假设订单占比。
- 源表报告的零金额保留为零，不删掉后抬高成交能力。源零值是否为占位需要核验；脚本只称“报告零成交”。缺失金额不变成零，不完整窗口的均值明确为已知样本均值。
- 可提供 `--calendar calendar.json`（预期交易日字符串列表）和 `--statuses statuses.json`（`{symbol:{date:"trading"|"suspended"|"missing"|"unknown"}}`）。停牌由输入声明，不是程序独立确认；应在研究笔记保留公告来源。声明停牌但金额为正时拒算，以防误标。
- 停牌日按该交易所开市日的可交易能力计零，并另报排除声明停牌后的已知活跃日均量；两种分母不能混称同一“平均成交额”。无日历时窗口只是最近观察到的报价日，无法识别整行缺失的交易日，此时不把分母标成完整交易日窗口。
- 部分资产失败仍保留该资产及原因，不默默删掉后改变候选集合。缺项/短样本数量显示在结果中；数据丰富不等于流动性有保证。

例：四个预期交易日，成交额100、0、声明停牌、缺失。已知三个交易日能力均值为100/3；已知且非停牌日均值50；未知日不填零，完整四日均值不可知。它们不能写成“平均每天100”。

## 订单与报价成本

订单占比为 `假设订单人民币金额 / 窗口成交额分母`。同时给均额、中位和低分位，避免一两天放量掩盖平日偏低。某ETF日成交额很大、订单占比很小，仍不能证明盘口挂量、买卖价或冲击可忽略；ETF还需看底层篮子、做市与申赎限制。

有盘口时，以同一报价中间价为参考，单边跨价成本约为**半个完整买卖价差**乘名义金额；相同盘口、相同金额的假设往返为两个半价差，即一个完整价差。佣金按每腿 `max(金额×费率, 最低佣金)` 单列，不把完整价差重复扣两次。

例如买一0.999、卖一1.001，一万元订单、万一免五：单边半价差参考10元，佣金1元，共11元；同盘口假设往返为22元。它不是实际成交损益预测：没有纳入真实买卖时点、挂单规模、整手、未成交、额外滑点、全部税费或申赎成本。盘口缺失时价差成本保持未知，不能拿历史收盘制造盘口。所有成本示例都标参考，保留源报价时点，不用于实时交易放行。
